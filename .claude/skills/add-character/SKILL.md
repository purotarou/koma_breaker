# 新しい操作キャラの入れ方（主人公カケルで得たノウハウ）

Tripo で作ったキャラを「ゲームで使える操作キャラ」にするまでの手順と、つまずいた所の記録。
最初の版（単色・6部品）は「顔が粗い・3人称で腕が透ける・棒人間の歩き・銃を持つ腕が変」と言われてやり直した。**最初から2回目のやり方でやること。**
実装の置き場所: `js/hero.js`（描画・動き）、`js/gfx.js`（`kb_mat` 10/11、`addIdxPrim`、`setModelTex`）、`tools/blender_export_hero.py`（書き出し）、`blender/hero_kakeru.blend`（見本）。

## 0. 先にやること
- **ライセンス**: 生成したプランを確認（有料プランなら商用可、無料プランのモデルは使わない）。`ASSETS.md` に出どころ・プラン・日付・根拠 URL を書く。push の前に済ませる（他セッションが先に push していることがあるので、確認前にファイルを置かない）。
- 元の GLB は `blender/src/` にそのまま置く（改変前の保存）。
- 参考画像（正面・横・後ろ）があるなら、テクスチャの見た目と比べるために手元に置く。

## 1. Tripo での出力（次回の注文）
- **T ポーズ**、手は開く、足は肩幅。服の裾・袖は**厚みのある形**（ぺらぺらの布だと穴になる）。
- 部品分割は任意。分割モデルは切り口が開いている（そのまま使うと3人称で中が見える。下の3）。
- 三角メッシュでよい。テクスチャは付けたままにする（捨てない）。

## 2. 方針: 色を捨てず、テクスチャ＋骨で動かす
- 「テクスチャを単色マテリアルに置き換える」方式は顔が粗くなる。**主人公クラスの操作キャラはテクスチャを焼き付けて使う**（1024px、顔を大きく取る）。
- 「部品ごとに分けて角度だけ付ける」方式は、肩・股に継ぎ目が出て、肘・膝が曲がらず棒人間になる。**骨を入れて頂点を曲げる**（CPU スキニング）。
- 三角形は約8,000（頭1,900＋体6,100）。ファイルは約0.9MB（テクスチャは JPEG 約0.45MB）。1体あたりのスキニングは約0.15ms（Mac）。**iPad は未計測**。

## 3. Blender 作業（実際に通った手順）
1. glTF を取り込み → 全部品に変換の適用 → 部品番号の属性を付けて1つに結合（これが焼き付けの元 `KK_Source`）。
2. **穴をふさぐ**: 複製 → Solidify（厚み 0.008、offset 0）→ Remesh（Voxel 0.0045、スムース）→ 三角化 → Decimate で約8,000面。
   - 薄い布（袖）に Solidify を挟まずに Remesh だけすると、袖の下側がぐちゃぐちゃに崩れる。
   - 切り口が開いたままだと、ゲームは裏面を描かないので3人称で腕・首・腰が透ける（今回の主な原因）。
3. **UV**: Smart UV Project → 顔の島だけ拡大（頭の高さ z>0.8 かつ正面 y<0 は 2.6倍、頭のほかの島は 1.6倍）→ Pack Islands。
4. **焼き付け**: Cycles、Diffuse の**色だけ**（Direct/Indirect を切る）、選択物→アクティブ、`cage_extrusion` 0.024、`max_ray_distance` 0.08、`margin` 16。
   - **元と先の大きさを揃える**（元が身長1、先が2なら、元を2倍にしてから焼く）。揃っていないと焼けない/ずれる。
   - 焼いた後は上着のテカリがピンクに見えたり肩にピンクの丸が出たりする。赤い上着の「くすんだ薄い赤」を赤に塗り直す（r が高く、g≒b で彩度が低い所）。
5. **骨**（16本）: hips / spine / chest / head、upperarm・forearm・hand、thigh・shin・foot（左右）。関節位置はメッシュの断面から測る（腕は x ごとの z・y の範囲、脚は z ごとの x の範囲）。
   - 自動ウェイト（`ARMATURE_AUTO`）は**モデルが小さいと失敗する**（「ボーンヒートウェイトが解決に失敗」、全頂点が未割当）。最終サイズ（身長2.0）で行うか、10倍にして行ってから戻す。ウェイトのない頂点は、最も近い重み付き頂点から写す。
   - 拡大・縮小の後は、メッシュと骨の**両方に**スケールを適用し、最後に身長を数値で確認する（今回は縮んだメッシュを 5倍して戻す事故が起きた）。
6. **Blender でのテストポーズでは「歩き」を判断しない**。骨のローカル軸の向きが分かりにくく、膝を逆に曲げた画像を出してユーザーに指摘された。曲がり方の確認はゲームの `?hero=1` を横から見て行う。
7. 保存: `.blend` とテクスチャ `blender/<名前>_tex.png`（書き出しはこの PNG を読む。メモリ上の画像だけ直して書き出すと古いテクスチャのままになる）。

## 4. 書き出し（`tools/blender_export_hero.py`）
- Blender の glTF 出力は使わず、手組みの GLB: 頂点（位置・法線・UV・骨番号u8×4・重みf32×4）は1組、索引は2つ（頭＝`kb_mat` 10、体＝11）、テクスチャ（macOS の `sips` で JPEG 化）、骨は `extras.kb_bones`（名前・親・休み姿勢の関節位置）。
- 座標: Blender の (x,y,z) → ゲームの (x, z, −y)。前は +Z、キャラの右は −X。UV の v は `1−v`。
- 書き出したら **`.glb` と `.glb.js` を一緒に commit**（`file://` で開いたときに使う。中身が同じことを確認済み）。

## 5. ゲーム側の要点（`js/hero.js`, `js/gfx.js`）
- 頂点バッファ（位置＋法線、24バイト刻み）は毎フレーム CPU で曲げて書く。**描く人数分のバッファの組**を使い回す（`HERO.pool`、同じフレームで人数分増える）。
- テクスチャはテクスチャユニット3（`uHT`）。ユニット0〜2は影・Gバッファが使うので重ならないように。
- `kb_mat` 11 は赤い所（上着）をプレイヤー色 `PCOL[slot]` に差し替える。肌は g が b より強いので除く（除かないと顔が赤くなる）。顔の点々（ひげに見える）はこの判定が甘いと出る。
- テクスチャには陰影が入っているので、トーンの点は濃い影だけ（`a=mix(a,0.85,0.45)`）。
- 動き（骨をコードで回す。座標系は前 +Z、上 +Y）:
  - 太もも前＝X 軸のマイナス回転、膝は X 軸のプラス（後ろへ曲がる）、足首は逆に打ち消して水平に近づける。
  - 歩き: 左右の太ももを `sin(wt*10)` で逆位相、膝は `max(0, cos)` で足を引き上げる側だけ曲げる、腰を Y 軸にひねる、上下に `|cos|` で揺らす。空中は別ポーズ。
  - 構え: 腕は肩〜手首の**2ボーン IK**。肘の向きは極ベクトルで決める（右腕の肘は下・外、左は下・内）。両手は「構えの座標系」（胸の前＋視線の上下で回す）の中に置く。銃も同じ座標系。
  - 3人称カメラは右肩越しなので、銃を右の肩口（`HERO_GUN_X`）に出さないと体の陰で見えない。
- 描画は `drawHero(o)`（players.js）が選ぶ。**読み込み失敗時は箱の主人公に戻る**（`HERO.ready`）ので、必ず残す。
- 出力契約: `o={x,y,z,yaw,pitch,slot,wt,mv,dead,flash}` を受けて、銃口 `o.gx/gy/gz` を返す。

## 6. 確認の仕方（これで見落としが減った）
- ブラウザで `python3 -m http.server`（`preview_start`）を立て、`?hero=1` を開く。`file://` は開けないことがある。
- 画面の確認用にコンソールから: `startGame()`、`setInterval(()=>{enemies.length=0;pl.hp=99999},30)` で敵を消す、`document.getElementById('ui').style.display='none'` で UI を隠す、`#stage` に CSS の `transform:scale(2〜3)` を付けて拡大、`drawGun=function(){}` で手前の銃を消す、`drawHeroTest` を差し替えて 横向き・斜め・後ろ・歩き を並べる。ビューポートは 1600×950 に。
- 見る角度: 正面（顔）、真横（膝・肘・銃）、後ろ（3人称で見える所）、歩き中、上下を向いた状態、4色（上着の差し替え）、3人称（SET.view=1）で実際に走る。
- 数値でも確認: 骨の位置（`HERO.GT`）、肘・手首、銃口の位置、`console` のエラー、1体のスキニング時間。
- 確認が終わったら、ブラウザのサイズを戻し、サーバーを止める（`feedback_close-browser-after-testing`）。

## 7. 複数のキャラにするときの注意（**未実装・未検証**）
- いまの `HERO` はキャラ1体分のグローバル、`uHT` も1枚。キャラが2体以上になるなら:
  - `HERO` を「キャラごとの定義」にして `drawHero(o)` が `o.char` で選ぶ。
  - テクスチャが1枚だと足りないので、(a) キャラ全員を1枚のアトラスにまとめる、または (b) キャラごとに描画を分けてテクスチャを差し替える（`flushLayer` の前後で bind）。(a) の方が簡単で、描画回数も増えない。
  - 同じ骨構成にそろえれば、`hRot` の動きのコードを共有できる。骨の名前・関節位置は `kb_bones` から読むので、体型の違いは吸収できる。
- 敵や味方キャラは、頂点数が多いとスキニングが重くなる。数が多いもの（ザコ）は単色・部品分けのままにする。
